# Implementation Plan

## 1. 원칙
- 현재 단계에서는 문서만 작성한다.
- 구현 단계에서도 SQLite + `sqlite3`를 유지한다.
- 기존 공개 채팅은 유지하고 신규 기능을 덧붙인다.
- 각 단계는 회귀 테스트와 보안 테스트를 포함한다.

## 2. 단계별 계획
### Phase 1. 인증 및 보안 기반 정비
**목표**
- 비밀번호 해시 저장
- `SECRET_KEY` 환경변수화
- 세션 쿠키 보안 설정
- CSRF 보호
- 공통 로그인 인증 가드
- 로그인 요청 제한
- 운영 환경 debug 비활성화
- 사용자명 3~20자 영문/숫자/밑줄, 비밀번호 최소 8자 정책 반영
- 기존 GET `/logout`을 POST 방식으로 변경
- 로그아웃 폼에 CSRF 토큰 적용
- 기존 로그아웃 링크를 POST form 버튼으로 변경

**수정 예정 파일**
- `app.py`
- `templates/base.html`
- `templates/login.html`
- `templates/register.html`
- `templates/profile.html`
- `templates/new_product.html`
- `templates/report.html`
- `readme.md` (최종 단계에서 실제 파일명을 `README.md`로 변경 예정임을 반영)
- `docs/security_checklist.md` (추적 갱신)

**완료 조건**
- 평문 비밀번호 제거
- `SECRET_KEY`가 설정되지 않으면 애플리케이션 실행을 중단하고, 비밀값을 노출하지 않은 채 환경변수 설정 방법만 안내한다.
- 자동 임시 키나 하드코딩된 기본 키는 사용하지 않는다.
- 주요 POST 요청이 CSRF 검증을 통과해야만 성공하고, CSRF 토큰 없는 로그아웃 요청은 거부한다.
- 로그인 필수 공통 가드가 도입됨
- 동일 IP + 사용자명 기준 10분 동안 실패 5회까지 기록하고 6번째 로그인 시도부터 제한하며, 성공 시 실패 기록을 초기화한다.
- 사용자 존재 여부와 관계없이 로그인 실패 메시지는 동일하게 유지한다.
- 로그아웃 성공 후 세션이 제거된다.
- 운영 환경에서 debug 비활성화 가능

### Phase 2. 데이터 모델 확장과 입력값 검증
**목표**
- `user`, `product`, `report` 확장
- 역할/상태/잔액/신고 상태/가격 정수화 반영
- 입력값 검증 추가
- 신규 가입자 가상 잔액 `100000` 반영
- 기존 `market.db`를 `market.baseline.db`로 로컬 백업한 뒤 목표 스키마의 새 `market.db`를 생성하는 초기화 전략 문서화
- 초기 관리자 계정을 코드/DB 하드코딩 없이 `flask --app app create-admin` CLI 명령으로 생성하는 방식 반영
- 관리자 CLI는 `getpass`를 사용하는 대화형 입력 방식으로 설계

**수정 예정 파일**
- `app.py`
- `readme.md` (최종 단계에서 실제 파일명을 `README.md`로 변경 예정임을 반영)
- `docs/database_design.md` (추적 갱신)

**완료 조건**
- 목표 스키마에 맞는 테이블/컬럼 준비
- 상품 제목 1~100자, 설명 최대 2000자, 신고 사유 1~500자 검증이 반영됨
- 신고에 상태와 대상 종류가 반영
- 기존 DB 백업 후 신규 DB 생성 절차가 구현 문서와 실행 절차에 반영됨
- `flask --app app create-admin` 명령으로 초기 관리자 생성 경로가 준비됨
