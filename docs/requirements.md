# Requirements

## 1. 범위 확정
- 기존 전체 공개 채팅은 유지하며, 이 기능으로 과제의 사용자 소통 필수 요구사항을 충족한다.
- 상품별 1:1 문의 기능과 문의 메시지 DB 저장은 선택 기능으로 별도 구분한다.
- 선택 기능은 시간이 부족하면 구현하지 않을 수 있다.
- 선택 기능을 구현하지 않아도 최종 필수 요구사항 미충족으로 판단하지 않는다.
- 신고는 관리자 검토 후 사용자 정지 또는 상품 차단으로 이어질 수 있어야 한다.
- 동일 사용자의 중복 신고를 제한한다.
- 송금은 가상 잔액 기반 모의 송금으로 구현한다.
- 자기 자신 송금, 0원 이하 송금, 잔액 초과 송금을 차단한다.
- 관리자는 사용자, 상품, 신고, 송금 내역을 관리한다.
- 상품 제목/설명 검색과 가격 범위 필터를 지원한다.
- 일반 사용자와 관리자 역할을 구분한다.
- SQLite와 `sqlite3` 방식은 유지한다.

## 2. 요구사항 ID 체계
- `EX-###`: 기존 기능 유지 요구사항
- `CH-###`: 기존 기능 변경 요구사항
- `NW-###`: 신규 기능 요구사항
- `SEC-###`: 보안 요구사항
- `NFR-###`: 비기능 요구사항
- `T-###`: 테스트 항목 ID

| ID | 구분 | 요구사항 | 수용 기준 | 테스트 |
|---|---|---|---|---|
| EX-001 | 기존 | 회원가입 기능을 유지한다. | 신규 사용자가 계정을 생성할 수 있다. | T-001, T-002 |
| EX-002 | 기존 | 로그인/로그아웃 기능을 유지한다. | 인증 성공 시 세션 생성, 로그아웃 시 세션 제거 | T-003, T-004 |
| EX-003 | 기존 | 프로필 수정 기능을 유지한다. | 로그인 사용자가 자신의 소개글을 수정할 수 있다. | T-005 |
| EX-004 | 기존 | 상품 등록 및 상세 조회 기능을 유지한다. | 로그인 사용자가 상품을 등록하고 상세 화면에서 확인 가능 | T-006, T-007 |
| EX-005 | 기존 | 전체 공개 채팅 기능을 유지한다. | 로그인 사용자가 공개 채팅 메시지를 송신/수신 가능 | T-008 |
| CH-001 | 변경 | 신고 기능은 즉시 제재가 아니라 관리자 검토 대기 상태로 저장한다. | 신고 생성 시 상태가 `pending`으로 저장되고 관리자 검토 전까지 제재 미발생 | T-009, T-010 |
| CH-002 | 변경 | 동일 사용자는 동일 대상에 대해 검토 중 신고를 중복 제출할 수 없다. | 동일 `reporter`+`target`+`pending` 조합은 거부 | T-011 |
| CH-003 | 변경 | 사용자 역할을 일반 사용자와 관리자로 구분한다. | 관리자 전용 화면/작업은 관리자만 접근 가능하고, 정지 사용자는 신규 로그인 불가 및 기존 세션은 다음 보호 요청에서 종료 | T-012, T-013 |
| CH-004 | 변경 | 상품 조회는 검색과 가격 필터를 지원하도록 확장한다. | 제목/설명 검색, 최대 100자 검색어, 최소/최대 가격 필터 동작 | T-014, T-015 |
| NW-001 | 선택 | 상품별 1:1 문의 기능을 추가한다. | 상품 상세에서 구매자와 판매자가 문의 스레드를 생성 가능 | T-016, T-017 (Phase 7 구현 시에만 수행) |
| NW-002 | 선택 | 상품별 문의 메시지를 DB에 저장한다. | 문의/답변이 새로고침 후에도 조회 가능 | T-018 (Phase 7 구현 시에만 수행) |
| NW-003 | 신규 | 가상 잔액 기반 모의 송금 기능을 추가한다. | 신규 가입자 기본 잔액은 100000이고, 로그인 사용자가 다른 사용자에게 잔액 범위 내 송금 가능 | T-019 |
| NW-004 | 신규 | 송금 제한 규칙을 구현한다. | 자기 자신 송금, 0 이하, 잔액 초과는 거부하고 송금 메모는 최대 200자 | T-020, T-021, T-022 |
| NW-005 | 신규 | 관리자는 사용자 목록과 상태를 관리한다. | 관리자 화면에서 사용자 정지/해제 가능 | T-023 |
| NW-006 | 신규 | 관리자는 상품 상태를 관리한다. | 관리자 화면에서 상품 차단/해제 가능하고 차단 상품은 일반 사용자 목록/상세에서 숨김 | T-024 |
| NW-007 | 신규 | 관리자는 신고를 검토하고 처리 결과를 기록한다. | 신고 승인/기각 및 처리 사유 저장 | T-025 |
| NW-008 | 신규 | 관리자는 송금 내역을 조회한다. | 송금 감사 내역을 목록/필터로 확인 가능 | T-026 |

## 6. 역할 정의
### USER
- 회원가입/로그인/로그아웃
- 프로필 수정
- 상품 등록/조회/검색
- 공개 채팅 참여
- 신고 제출
- 가상 잔액 조회 및 송금
- 선택 기능 구현 시: 상품별 1:1 문의 생성 및 응답

### ADMIN
- USER 권한 전체
- 사용자 정지/해제
- 상품 차단/해제
- 신고 목록 조회/검토/처리
- 송금 내역 조회
- 감사 로그 조회

## 7. 범위 밖
- 실제 PG 결제 연동
- 외부 메시지 서비스 연동
- SQLAlchemy 기반 전면 리팩터링
- 다중 서버/분산 아키텍처
- 다른 사용자에게 관리자 권한을 부여하거나 회수하는 기능

## 8. 최종 완료 기준
- 필수 완료 범위는 EX-001~EX-005, CH-001~CH-004, NW-003~NW-008, SEC-001~SEC-005, SEC-007~SEC-014, NFR-001~NFR-004다.
- SEC-006 객체 소유자 권한 검증은 객체 소유권이 필요한 기능을 구현할 때 적용하는 조건부 요구사항이다.
- 선택 기능인 NW-001, NW-002는 Phase 7을 구현할 때만 완료 대상으로 포함한다.
- Phase 7을 구현하지 않으면 SEC-006과 T-107, 그리고 T-016, T-017, T-018은 수행 대상에서 제외한다.
- Phase 7을 구현하면 SEC-006과 T-107, 그리고 T-016, T-017, T-018을 반드시 수행한다.
- 최종 완료 판정은 필수 요구사항과 필수 테스트 충족 여부를 기준으로 한다.
