# Security Checklist

## 1. 목적
과제 필수 보안 항목을 구현 가능한 작업 단위와 테스트 단위로 정리한다.

## 2. 체크리스트
| ID | 항목 | 현재 상태 | 목표 상태 | 구현 포인트 | 검증 테스트 |
|---|---|---|---|---|---|
| SEC-001 | 비밀번호 해시 저장 | 미충족 | 충족 | `werkzeug.security` 또는 동급 해시 적용, 평문 제거 | T-101 |
| SEC-002 | `SECRET_KEY` 환경변수 관리 | 미충족 | 충족 | `os.environ` 로드, 미설정 시 실패 | T-102 |
| SEC-003 | CSRF 보호 | 미충족 | 충족 | 모든 POST 폼/상태 변경 요청 토큰 검증 | T-103 |
| SEC-004 | 서버 측 입력값 검증 | 부분 충족 | 충족 | 사용자명/비밀번호/상품/검색/채팅/신고/송금 입력값을 정책 길이와 형식에 맞게 검증 | T-104, T-105 |
| SEC-005 | 인증 검증 | 부분 충족 | 충족 | 로그인 필수 공통 가드 보강 | T-106 |
| SEC-006 | 객체 소유자 권한 검증 | 부분 충족 | 충족 | Phase 7 구현 시 문의 스레드 등 소유 리소스는 소유자/참여자만 접근 허용 | T-107 |
| SEC-007 | 관리자 권한 검증 | 미충족 | 충족 | 관리자 데코레이터 또는 가드 함수 | T-108 |

| SEC-009 | 로그인 요청 제한 | 미충족 | 충족 | 동일 IP + 사용자명 기준 10분 동안 5회 실패 시 제한 | T-110 |
| SEC-010 | 채팅 요청 제한 | 미충족 | 충족 | 사용자당 10초 동안 최대 5개 전송 제한 | T-111 |
| SEC-011 | 내부 오류 정보 비노출 | 미충족 | 충족 | 예외 핸들러 + 일반 오류 페이지 | T-112 |
| SEC-012 | 관리자 작업 감사 로그 | 미충족 | 충족 | 신고 처리/정지/차단/복구 기록 | T-113 |
| SEC-013 | 운영 환경 debug 비활성화 | 미충족 | 충족 | 실행 환경 분기, 기본 `False` | T-114 |
| SEC-014 | SQL 파라미터 바인딩 | 충족 유지 | 충족 유지 | 신규 SQL도 모두 `?` 바인딩 사용 | T-115 |

## 3. 입력 검증 기준
### 사용자명
- 3~20자
- 영문/숫자/밑줄만 허용
- 중복 불가

### 비밀번호
- 최소 8자
- 해시 저장만 허용

### 상품
- 제목 1~100자
- 설명 최대 2000자
- 가격은 정수, 0 초과

### 검색
- 검색어 최대 100자
- 최소/최대 가격은 정수
- 최소 가격은 최대 가격 이하

### 문의/채팅
- 채팅 메시지 1~500자
- 문의 메시지 1~500자
- 공백만 입력 금지
- 사용자당 10초 동안 최대 5개
- 문의 관련 검증은 Phase 7 선택 기능 구현 시에만 적용

### 신고
- 대상 종류 필수
- 대상 ID 형식 검증
- 사유 1~500자
- 중복 신고 제한

### 송금
- 정수 금액만 허용
- 0 초과
- 자기 자신 금지
- 잔액 초과 금지
- 메모 최대 200자

## 4. 권한 검증 체크포인트
| 기능 | 검증 포인트 |
|---|---|
| 프로필 수정 | 본인 세션만 허용 |
| 상품 등록 | 로그인 사용자만 허용 |
| 상품별 문의 | Phase 7 선택 기능 구현 시에만 문의 참여자 조회/작성 허용 |
| 신고 검토 | 관리자만 허용 |
| 사용자 정지/해제 | 관리자만 허용 |
| 상품 차단/해제 | 관리자만 허용 |
| 송금 | 로그인 사용자만 허용 |
| 송금 내역 관리 조회 | 관리자만 전체 조회 허용 |

## 5. 감사 로그 대상 작업
- 신고 승인/기각
- 사용자 정지/해제
- 상품 차단/해제
- 송금 관련 관리자 조회 또는 조정이 생길 경우 해당 작업

## 6. 구현 우선순위
1. 비밀번호 해시 / `SECRET_KEY` / debug 제어
2. CSRF / 입력 검증 / 인증·권한 가드
3. 관리자 감사 로그
4. 로그인/채팅 rate limiting
5. 오류 처리 및 사용자 메시지 정리
