# Test Plan

## 1. 목적
기존 기능 회귀 방지와 신규/보안 기능 검증을 위한 테스트 항목을 정의한다.

## 2. 테스트 범위
- 기능 테스트
- 권한 테스트
- 입력 검증 테스트
- 보안 회귀 테스트
- 관리자 CLI 테스트
- DB 스키마 및 제약조건 테스트

### 3.5 추가 Phase 2 테스트
- 일반 회원가입으로 `role=admin` 생성 불가
- 신규 사용자 `balance=100000`
- 신규 사용자 `role=user`
- 신규 사용자 `status=active`
- `create-admin` CLI 정상 생성
- 관리자 비밀번호 해시 저장
- 관리자 중복 생성 거부
- `create-admin`의 미초기화/구형 DB 거부
- `init-db`의 DB 없음 성공
- `init-db`가 기존 DB를 기본적으로 덮어쓰지 않음
- `init-db --replace`는 `market.phase1.db` 백업이 있을 때만 교체 허용
- CHECK 제약조건 위반 시 DB 수준 거부
- 외래키 위반 시 DB 수준 거부
- `python app.py` 구형 스키마 조기 중단
- `flask --app app run --no-reload` 구형 스키마 조기 중단


### 3.6 조건부 완료 기준

- Phase 7을 구현하지 않으면 T-016, T-017, T-018, T-107은 미수행이어도 최종 완료 판정에서 제외한다.

## 4. 테스트 방법
| 유형 | 방법 |
|---|---|
| 라우트 테스트 | Flask test client 또는 requests 기반 시나리오 |
| DB 검증 | SQLite 직접 조회 |
| 권한 테스트 | 사용자/관리자/비로그인 세션 분리 |
| 채팅 테스트 | Socket.IO 클라이언트 시나리오 |
| 보안 테스트 | 비정상 입력, 토큰 누락, 권한 위조, 요청 반복 |
| CLI 테스트 | Flask CLI runner + 임시 DB |
| 스키마 테스트 | schema_meta, CHECK, FOREIGN KEY, PRAGMA 검증 |
| 서버 기동 테스트 | `python app.py`, `flask --app app run`, `python -m flask --app app run`의 구형 스키마 조기 중단 확인 |
